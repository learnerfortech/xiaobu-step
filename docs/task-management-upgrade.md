# 小步任务管理升级｜实施方案

2026-11-14。基于 `fix/task-planning-progress` 的 `045945f`；继续原有页面和存储模型。

本文区分已有产品决定、官方资料可核实的机制及本轮设计选择。它是本轮开发交付说明，不是儿童效果研究或家庭设备部署证明。实际测试、提交与部署范围以对应 PR 的证据为准。

## 1. 目标与已有决定

孩子能看懂今天合理安排的内容，直接找到第一步，保留部分进度，在需要时求助，并看见已经做过的部分。家长能找到需要回应的事，结合当天负担调整安排。

已有决定继续有效：

- 家长改变日期与安排；孩子可选择允许的执行顺序、表达困难、申请调整。
- 录入日、计划日、老师真实期限分开。未知期限留空；有真实时刻则保留原时刻。
- 周总量、固定份额和每日展示引用同一记录。改期不增任务、不清进度、不减少总量。
- 同一固定份额只奖励一次。需要检查的纸笔任务仍在家长确认后发经验；在线任务和不要求照片的任务不新增照片门槛。
- 孩子自报、家长确认、奖励发放分别处理。外部网站没有完成数据接通时，记录仍为自报。
- 完成和提交项勾选、划线并留在当前清单；待检查与确认完成必须在列表直接区分。
- 周份跨日不成为顺延欠账、不减经验。本次不将这一例外扩大成学校作业或其他类别奖励规则的全局改写。
- 既有阅读打卡复用；纯习惯休息后是否补次数仍未定稿，不在本轮实施。

## 2. 研究与软件参考

### 科学依据

- [EEF 元认知与自我调节学习指南，2025](https://educationendowmentfoundation.org.uk/education-evidence/guidance-reports/metacognition)：在具体学习任务中示范计划、监测和评价，并依据表现调整支持。适用背景主要是学校教学；不能据此宣称几个按钮已培养独立规划。
- [Harkin 等，2016](https://eprints.whiterose.ac.uk/id/eprint/91437/)：进度监测实验综合研究支持进度记录对目标达成的平均益处；并非本家庭 App 的试验，也不证明打勾等于掌握知识。
- [Patall 等，2008](https://selfdeterminationtheory.org/wp-content/uploads/2019/10/2008_PatallCooperRobinson_PsychBulletin.pdf)：选择研究总体支持动机等结果。孩子的选择可放在顺序、允许的方法和求助中；不由此改变家长日期权限，也不设统一选项数量。

## 3. 任务和展示规则

| 类型 | 内容身份 | 本轮展示与调整 |
| --- | --- | --- |
| 学校单次作业 | 保留原任务及老师要求 | 沿用学校任务既有跨日处理；保留一般求助 |
| 周或阶段总量 | 总要求关联固定份额，每份稳定 ID | 今天只算今天的安排；过去计划未完成及未安排份数进入待家长安排，周总量仍可查看 |
| 习惯打卡 | 复用原任务与周期规则 | 不新增重复阅读项，不改变尚未决定的休息补次规则 |
| 课程行程 | 原行程记录 | 展示占时与提醒，单独呈现，不混成今日待做作业数 |

“今日安排”不复制任务。“待家长安排”也不改变任务的计划日、总量、真实期限、完成状态或奖励，只明确它尚未被重新安排到今天。

本轮在展示层完成分流，服务端原始任务查询兼容保留；周概览及家长待安排区域必须持续保留这些份额。重复数据按稳定 ID 去重。

## 4. 孩子端

### 哥哥

保留原三张分类卡、伙伴、每日约定和日期回看。首页增加轻量汇总，分别显示待做、待检查、已完成。

“接着做”仅从今天已安排且仍需行动的任务中选择已有进行中或部分进度的项。不能从未安排、旧计划、未来、待检查或已完成周份中自动选取。无候选不生成指定任务；孩子仍可自行进入分类选择顺序。

分类内分为“接下来”和“已经做过”。后者直接写出“已提交·待检查”或“已完成”，继续勾选划线；不能只在详情解释区别。仍有待检查项时，首页不能宣称已全部验收完成。

自由阅读单独呈现；真实课程才进入行程区。过往周份在周概览及待安排入口可找回。

### 弟弟

沿用书包、学校任务、整理书包、小游戏及朗读流程，修正待检查计数和播报。相同的周份规则生效，但只提供简短的待妈妈安排入口，不增加强制估时、规划表或每日反思。

### 任务详情

老师原要求置顶；已有 `first_step` 标为“先做这一步”，不新建同义字段、不要求家长重新填写整批任务。材料按用途保留，答案单独收起，原材料和音频继续可用。

部分进度使用原 `progress_note`。提交和奖励继续原状态机；改日期、拆执行步骤、重试和撤销不新增奖励份额。

## 5. 求助与家长安排

明确属于校外类别、计划在今天、仍需孩子行动的周份，可以显示“申请今天少做一点”。它复用现有求助说明与保存流程，仅表达调整意图。学校作业保留一般求助，待检查或已完成任务不能重复申请减量。

家长今天页继续按孩子查看。求助和待确认默认展开，其他任务保持收起。求助显示孩子原话；需要重排的周份有明确入口，不能因不计入今天而失踪。

家长的“已回应，继续做”只表示回应求助，不表示批准改期。实际改变日期仍使用原编辑或周份日期表；成功保存、读回后，才依据已有 `adjustments` 历史显示“已调整，今天不用做”。收到申请本身不产生这条记录。

调整界面提示先看学校作业、课程、恢复与睡前准备，只呈现已读取的负担信息。没有完整课表或未读取未来日期时不能写“空闲”。不自动平均、不把所有剩余量塞到明天、不把家长计划修改成老师延期。

本轮不另建完整审批中心；逐份批准、部分批准和结构化审批历史仍是后续范围。

## 6. 真实期限与状态

| 情况 | 处理 |
| --- | --- |
| 未开始 | 今天安排里正常保留；过去未完成周份转入待家长安排视图 |
| 部分完成 | 保存进度，仍为同一份；改期保留进度 |
| 已提交待检查 | 当天留痕且直接标待检查；必要检查未完成不发经验 |
| 已确认或按规则完成 | 保留记录并按同一份额一次结算 |
| 误点撤销 | 沿用现有允许撤销范围及奖励账本，不清照片、材料或部分进度 |
| 家长调整日期 | 不改总量和真实期限；依据成功保存的调整历史留痕 |
| 老师期限已到 | 明确实际期限和剩余内容，提示寻求家长支持及协调；不羞辱、不暗改日期 |

统一读取真实期限：已有带时区的 `plan.deadline` 保留准确时刻并按家庭时区展示；否则使用真实 `due_day`，不得从计划窗口猜期限。发现历史日期与精确时刻矛盾时明确提示。日期编辑器不能覆盖已知精确期限；允许家长保存时将旧日期对齐原精确期限。复杂的老师期限更正流程不在本版新建。

## 7. 开发范围

- `frontend/js/ui/task-planning.js`：统一今日分流、期限显示、已存在的进度与材料语义。
- `frontend/js/ui/child-jared.js`、`child-joey.js`：保留现有风格并调整入口、计数和状态文案。
- `frontend/js/ui/parent.js`：求助展开、待重新安排、现有改期衔接及期限保护。
- `frontend/css/app.css`：仅补相应区块样式，支持窄屏、长标题、可辨认文字与键盘焦点。
- `lan-server/task_planning.py`：保留精确期限，防止日期字段与原期限悄悄冲突。
- 测试复用现有合成数据与保存读回流程。无家庭库迁移、自动重拆原作业或照片移动。

## 8. 验收清单

1. 未安排、过去未重排和未来周份不计入今天；周总量、材料和任务入口仍可找回。
2. “接着做”不吸入上述份额，也不选择待检查项，不改变日期。
3. 两个孩子全部提交但未确认时，文字、计数和朗读都不会说全部验收完成。
4. 已提交与已完成在当前列表直接区分；完成留痕，未完成容易找到。
5. 家长进入对应孩子即能看到求助；兄弟数据不混，待检查照片门槛保留。
6. “少做一点”只发出求助；家长改期成功后才显示实际调整。
7. 部分进度、照片和材料在改期、刷新及重开后仍在；操作重试不覆盖别人更新。
8. 固定份只发一次经验，纸笔需检查后发放；外链不伪称同步。
9. 自由阅读不归入行程；课程不混入待做作业计数，原习惯政策保持。
10. 日期和精确时刻正确显示，未知期限保持未知，日期编辑不能改写已知精确期限。
11. 浅底按钮与文字可辨，长材料标题能换行，窄屏不横向溢出；需实际浏览器及目标平板核验。
12. 使用后是否更易开始、负担更合适、孩子更愿表达需要、家长整理更省事，另作轻量家庭观察；不以积分或清零率代替这些目标。

## 9. 应用到家庭版本

公开仓库与家庭本地版本存在差异。执行端必须先核对真实启动目录及当前版本，并保留原代码和数据备份；在副本验证后选择性整合本次差异，保留本地导入、同科材料归并及其他适配。不得整目录覆盖正在使用的安装。

源码检查、合成测试、浏览器核验、家庭 Mac 更新、安卓平板验收分别记录。未实际完成的步骤保持待验，不用文档或 PR 状态代替部署证据。
